# Комплекс лабораторных работ по тестированию OpenBMC (Лабораторные 3, 4, 5)

Данный репозиторий содержит решение и материалы для сдачи трех лабораторных работ по курсу тестирования системного ПО и интерфейсов управления серверным оборудованием OpenBMC:

- **Лабораторная работа 3:** Составление тест-плана тестирования OpenBMC (стандарт IEEE 829).
- **Лабораторная работа 4:** Разработка автотестов для Web UI с использованием Selenium.
- **Лабораторная работа 5:** Разработка автотестов для REST API (DMTF Redfish) с использованием PyTest.

В проект также включен автономный сервер-эмулятор **OpenBMC Mock Server** (Web UI + Redfish API + IPMI), позволяющий полностью запускать и демонстрировать все тесты даже при отсутствии физического серверного стенда или VPN-доступа.

### Лабораторная работа 4: Автотесты Selenium Web UI
Запуск в фоновом режиме (Headless):
```bash
python lab4_selenium_webui/openbmc_auth_tests.py --url http://127.0.0.1:8080
```

Запуск **с отображением браузера на экране** (чтобы преподаватель видел клики и ввод):
```bash
python lab4_selenium_webui/openbmc_auth_tests.py --url http://127.0.0.1:8080 --no-headless
```

Запуск через `pytest`:
```bash
pytest lab4_selenium_webui/openbmc_auth_tests.py -v
```

**Реализованные сценарии:**
1. `test_01_successful_login`: Успешная авторизация пользователя `root`, проверка дашборда и корректный выход из системы (Logout).
2. `test_02_invalid_credentials`: Попытка входа с неверным паролем, проверка отображения сообщения об ошибке.
3. `test_03_account_lockout`: Защитная блокировка учетной записи (Account Lockout) после 3 неудачных попыток ввода пароля.
4. `test_04_power_control_via_webui`: Управление питанием сервера (выключение и включение хоста через кнопки интерфейса).
5. `test_05_event_log_after_action`: Инициация действия и проверка фиксации события в журнале системных событий (Event Logs).
6. `test_06_component_temperature_limits`: Проверка датчика температуры CPU0 и контроль допустимого диапазона (10°C .. 85°C).
7. `test_07_hardware_inventory_display`: Проверка отображения компонентов аппаратной инвенторики (CPU, RAM).

---

### Лабораторная работа 5: Автотесты Redfish REST API
Запуск тестов с подробным протоколом выполнения и логированием:
```bash
pytest lab5_redfish_pytest/test_redfish.py --bmc-url http://127.0.0.1:8080 -v -s
```

**Реализованные сценарии:**
1. `test_01_redfish_authentication`: Отправка POST на `/redfish/v1/SessionService/Sessions`, проверка кода 200/201 и получение сессионного токена `X-Auth-Token`.
2. `test_02_system_information`: Отправка GET на `/redfish/v1/Systems/system`, валидация полей `Status` (`State`, `Health`) и `PowerState`.
3. `test_03_power_control_reset`: Отправка POST с параметром `{"ResetType": "On"}` на действие Reset, проверка статуса 202 Accepted и проверка изменения `PowerState` на `"On"`.
4. `test_04_cpu_temperature_within_limits`: Запрос `/redfish/v1/Chassis/chassis/Thermal`, поиск датчика процессора, валидация порогов `UpperThresholdNonCritical` и `Status.Health == "OK"`.
5. `test_05_cpu_temperature_redfish_vs_ipmi_consistency`: Сравнение показателей температуры CPU, полученных через Redfish API и через IPMI-интерфейс, проверка расхождения в пределах погрешности (<= 1.0°C).
